## ✨ Возможности

### 📝 Работа с задачами
- добавление задачи по кнопке или клавише `Enter`
- валидация: пустое значение и строка из одних пробелов не принимаются, пользователь сразу видит подсказку
- отметка выполнения, выполненные задачи визуально приглушаются и зачёркиваются
- удаление одной задачи или всех сразу (с подтверждением)
- счётчик «выполнено из всего»

### 🔍 Поиск и навигация
- поиск по названию в реальном времени, регистр не важен
- понятные пустые состояния: «задач пока нет» и «задача не найдена»
- кнопка плавной прокрутки к первой невыполненной задаче
- отдельная страница задачи `/tasks/:id` с состояниями загрузки и ошибки

### 🎞 Анимации
- плавное появление новой и исчезновение удалённой задачи, остальные элементы списка сдвигаются без рывков
- реакция элементов интерфейса на наведение, фокус и нажатие
- уважение к настройке системы `prefers-reduced-motion`

### 💾 Сохранение данных
- задачи не пропадают после перезагрузки страницы
- два режима хранения (локальный и через REST API), переключаются переменной окружения

## 🛠 Технологии

| Технология | Назначение |
| --- | --- |
| **React 19** | интерфейс, компонентный подход, хуки |
| **Context API + `useReducer`** | управление состоянием списка задач |
| **Собственные хуки** | `useTasks`, `useIncompleteTasksScroll`, объединение ref |
| **History API** | собственный клиентский роутер с динамическими параметрами (`/tasks/:id`) |
| **Vite 7** | сборка и dev-сервер, алиас `@` на `src` |
| **SCSS Modules** | изолированные стили компонентов, CSS-переменные для темы |
| **json-server** | REST API для режима разработки |
| **ESLint 9** | статический анализ, правила React Hooks |
| **gh-pages** | публикация на GitHub Pages |

## 🏗 Архитектура

Проект организован по методологии **Feature-Sliced Design**: каждый слой знает только о тех, что лежат ниже.

```
src/
├── app/        инициализация, роутер, глобальные стили и переменные
├── pages/      страницы: список задач, страница задачи
├── wdgets/     крупные самостоятельные блоки интерфейса (Todo)
├── features/   пользовательские сценарии: добавить, найти, статистика
├── entities/   сущность «задача»: контекст, хуки, TodoList, TodoItem
└── shared/     UI-кит (Button, Field, RouterLink), API, константы, хуки
```

Поток данных:

```
 UI (features, entities/ui)
        │  читают состояние и вызывают действия
        ▼
 TasksContext  ◄──  useTasks (useReducer + эффекты)
        │
        ▼
 tasksAPI  ──►  localAPI   (localStorage)
           └─►  serverAPI  (REST, json-server)
```

## 🔌 Слой данных

У обоих API-адаптеров один интерфейс (`getAll`, `getById`, `add`, `delete`, `deleteAll`, `toggleComplete`), поэтому интерфейс не знает, откуда приходят данные. Адаптер выбирается переменной окружения:

| Режим | `VITE_STATIC_BACKEND` | Где хранятся задачи |
| --- | --- | --- |
| Production (GitHub Pages) | `true` | `localStorage` браузера |
| Development | не задана | `json-server` на `localhost:3001` |

## ♿ Доступность и UX

- у каждого поля есть связанная подпись, у иконочных кнопок есть `aria-label`
- видимый фокус с клавиатуры (`:focus-visible`)
- чекбоксы подписаны скрытым от глаз текстом для скринридеров
- автофокус на поле новой задачи, после добавления фокус возвращается в него
- адаптивная вёрстка

## 🚀 Запуск

Нужен Node.js 18+.

```bash
git clone https://github.com/igorasha26/todo-list-react.git
cd todo-list-react
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`.

Чтобы работать через REST API, в соседнем терминале запустите `json-server`:

```bash
npm run server
```

### Скрипты

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер с HMR |
| `npm run build` | production-сборка в `dist` |
| `npm run preview` | локальный просмотр сборки |
| `npm run lint` | проверка кода ESLint |
| `npm run server` | `json-server` на порту 3001 |
| `npm run deploy` | сборка и публикация на GitHub Pages |

## 🌍 Деплой

Публикация идёт командой `npm run deploy`: проект собирается, из `index.html` создаётся `404.html` (так прямые ссылки на `/tasks/:id` открываются и на статическом хостинге), после чего папка `dist` отправляется в ветку `gh-pages`.

Базовый путь `/todo-list-react/` задан в `vite.config.js` и включается только для production-сборки.
